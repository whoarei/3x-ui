客户流量统计技术方案

以客户为中心，把总量历史与网站去向放进同一查询页面；在现有额度管理旁增加可追溯的分钟历史和域名分析，并保持业务转发与持久化处理的清晰边界。

单客户 / 所有客户1 / 7 / 30 天与自定义客户总量 + 网站与服务离线 HTML · 可打印

依据 2026-11-08 的源码、构建与部署记录编写。面板统计功能基线 0d485e33，内核功能基线 7dd1172；本文已同步堆叠柱状图实现，线上实际版本以部署记录为准。页面截图使用示例数据，不含真实客户凭据。

01

目标、范围与统计口径

本方案说明已经在 3x-ui 上实现的“客户流量统计”页面，以及配套的定制 Xray 内核。它回答两类问题：某个客户在一段时间内传输了多少数据，以及这些数据流向了哪些可识别的域名或服务。

按客户看历史

单个或所有客户，最近 1 / 7 / 30 天及自定义起止时间；上传 / 下载堆叠柱状图和客户明细共用筛选条件。

按站点看去向

服务与域名排行、上传 / 下载 / 合计、占比及筛选；未知品牌仍保留域名。

保留可解释性

独立历史、采样覆盖、资源上限提示和保存值 / 实际状态分离，便于解释数据缺口。

两个视图的职责

项目客户总量网站与服务
数据来源现有 Xray 用户统计和已经接受的远程节点增量本机定制 Xray 的客户 × 域名计量批次
普通官方内核可继续提供客户总量不提供本方案的扩展域名 RPC
业务关系复用原有客户用量入账链路附加的细分分析，不接管原额度判定
历史保留分钟桶默认长期保留域名分钟明细默认 30 天；服务日汇总默认 365 天
启停关系沿用原有客户采集任务网页保存开关后重启本机 Xray 生效

流量方向与单位

界面含义数据字段解释
发送给客户（客户下载）down代理向客户方向写出的字节数。
从客户接收（客户上传）up代理从客户方向接收的字节数。
合计up + down所选客户、时间和站点筛选范围内的双向总量。
堆叠柱的总高度该区间的上传 + 下载字节量下载在下、上传在上；不是瞬时速率，也不是从系统启动累计到该时刻的计数器。
显示单位B / KiB / MiB / GiB界面使用 1024 进制，数据库存整数 Byte。

口径边界

客户代理流量不等于服务器网卡流量：网卡还包含代理另一侧、协议封装、SSH、面板和其他服务。此页面用于用量分析；历史缺口、内存未落盘数据和协议识别边界需要一并解释。

02

页面结构与使用流程

页面入口位于侧栏和系统状态页；客户列表中的图表入口可直接进入对应客户的历史。移动端可从客户操作菜单进入。页面路由为 /panel/traffic-history，?view=sites 选择网站视图，clientId 可指定客户。

共同筛选条件

  1. 选择“所有客户”或一个客户；客户名称和备注可用于搜索，已删除客户仍保留历史入口。
  2. 选择最近 1 / 7 / 30 天，或在自定义范围中明确起止日期与时间。页面显示面板时区。
  3. 选择“客户总量”或“网站与服务”。客户和时间条件在两个视图之间共用。
  4. 总量视图显示上传 / 下载堆叠柱状图和有历史记录的客户明细。客户选项包含当前客户，但一个范围内没有用量记录的客户不一定出现在明细表中。

站点分析操作

网站视图可在“按服务”和“按域名”之间切换。点击服务进入该服务的域名排行，点击域名进一步过滤。标签和“显示全部”可清除筛选。搜索按域名 / 服务键做不区分大小写的子串匹配，最多 128 个字符。

图表、汇总卡片和排行应用同一组筛选。排行为范围内前 100 项，并同时返回完整项目数量。占比分母是筛选后总量；前 100 项的占比之和不一定为 100%。表格每页 20 项，窄屏在表格容器内横向滚动。

刷新与采集间隔

环节当前周期说明
内核细分汇总1 秒把连接的原子增量汇入当前 UTC 分钟桶；短连接关闭时补收剩余字节。
面板客户总量采集5 秒复用现有 XrayTrafficJob。
面板域名批次采集5 秒DomainTrafficJob 每次取最多 1000 条，提交后才推进确认。
客户选项 / 总量视图30 秒最近时间段同时滚动更新边界；自定义总量查询不定时刷新，可手动刷新。
网站查询 / 实际开关状态15 秒保存开关后会主动刷新；时间范围仍由页面共同条件决定。

内核采集时间、写库时间与浏览器刷新时间不同，因此新用量出现在页面上存在数秒到数十秒的延迟；15 秒页面刷新不是内核计量精度。

03

总体架构与技术取舍

前端复用 3x-ui 的 React、Ant Design、TanStack Query 与 uPlot。后端通过现有 Gin 认证入口提供查询，使用 GORM 和串行流量写入器更新原面板数据库。两条采集链路汇入同一个查询层，但各自维护计数和采样覆盖。

选择理由承担的边界
沿用原面板数据库客户身份、总量、额度和历史在现有运维体系内管理，复用备份。分钟历史会持续增长；需要监测磁盘与查询成本。
原子计数 + 后台批次转发路径不执行数据库或服务分类 I/O，汇总与持久化由旁路任务承担。不是跨内核崩溃的持久队列。
复用 loopback gRPC扩展已有 StatsService 注册点，不新增公网监听。需要面板与定制内核遵守同一批次协议。
紧凑分类索引避免运行时把整份 GeoSite 展开为大量对象。分类仍是规则判断，CDN 和加密元数据会影响归属。
保存设置后重启内核统一处理新旧连接与计量状态，沿用进程启动边界。会中断现有连接，最后未导出的细分数据可能丢失。
04

客户总量历史的采集与入账

本机采集

  1. XrayTrafficJob 复用用户统计获取本轮增量与采样时刻；任务互斥，避免本轮重叠采集。
  2. AddTrafficAt 进入串行流量写入器。数据库事务内同时更新原有客户 / 入站用量，并写入历史分钟桶。
  3. 写入前按客户身份规范化增量；历史行按 (client_id, source_id, bucket_start) 合并。多个入站关联同一客户时，不直接把入站累计数再作为第二份客户历史入账。
  4. 事务成功后清空任务的 pending 增量。写库失败时保留本轮数据和原采样时间，后续重试成功后才继续取下一轮。

原用量与历史同事务提交，避免出现“额度用量更新成功、历史却丢失”的半提交状态。额度到期、续期或远程配置等生命周期维护位于用量持久化之后；这部分操作失败不会抹去已提交用量。

远程节点

客户总量历史可记录面板已经接受的远程节点新用量，使用来源标识区分本机与节点。初次接入已有累计量不伪装成当前分钟的新流量；重复上报先按现有节点基线处理，再把已接受增量写入历史。网站细分目前只接入本机定制内核，不能据此推断远程节点也已具备域名统计。

历史与额度相互独立

操作原用量 / 配额历史记录
月度重置、手动清零由原客户用量与额度机制处理历史表不跟随清零
调整额度、临时增加流量改变可用额度与既有禁用逻辑已记录历史不改写
删除客户删除或停用现有客户实体历史身份快照保留，可查询已落盘记录
重建同名客户新实体使用新的客户内部 ID不把旧账号历史合并到新账号
改备注 / 名称使用当前客户资料显示时优先当前资料；删除后使用快照

稳定身份

历史键使用客户内部 ID。内核批次携带 email，面板写入时解析到该 ID，避免把界面名称或订阅链接文本当作历史主键。

05

定制内核计量与 Vision 快速转发

域名获取与会话生命周期

在 dispatcher 中为带有客户 email 的逻辑请求创建 DomainSession。目标本来就是域名时直接采用目标域名；目标是 IP 且端口为 80、443 或 8443 时，可为统计检查初始 HTTP / TLS / QUIC 元数据。空域名使用 __unknown__，统一转为小写并规范尾点。

统计专用嗅探只取得归类信息，不覆盖原目标地址，也不主动填充原本未开启嗅探的路由协议字段。原来已经配置的路由嗅探仍按上游行为执行。内部 v1.mux.cool 和 v1.xudp.cool 载体不直接创建统计会话，避免把承载层再次当作站点流量。

  1. 会话建立后先收集初始字节，等待域名判定；进入路由转发时标为 ready。
  2. 上传 / 下载通过原子计数累加，每秒取差量汇入客户、域名和 UTC 分钟桶。
  3. 短连接关闭时补收剩余增量；任务提前返回或空闲清理后，如果仍有后续字节，会话可重新加入跟踪。
  4. 空闲跟踪条目约两分钟后移除。界面中的 active 是跟踪集合大小，不等同操作系统 TCP 连接数。

保留原有客户统计

DomainCounter 在现有客户计数器旁增加会话计数，保留原 SizeStatWriter 类型，以兼容 Vision 对转发链路的判断。原客户统计被读取或额度被重置时，不以此删除网站历史；网站统计也不成为额度拦截的第二套权威来源。

为什么单独处理 splice

上游某些原始 TCP 复制路径在整个 ReadFrom 结束后才一次性得到字节数。若只在该位置计量，长连接尚未关闭时页面就看不到相应增量。

Linux / Android 的受跟踪 Vision 连接因此使用非阻塞 splice 循环：TCP → 内核管道 → TCP，每次实际写出的段都会更新原统计与会话计数。管道尝试设置到 1 MiB，始终有界并在退出时关闭；能力不支持且尚未传输时可回退。关闭网站统计后，新内核不挂接该计数包装，继续使用上游原始复制路径。其他平台沿用其缓冲复制路径。

采集内容

只保存客户标识、目标域名、时间桶和双向字节数。不记录 URL 路径、页面内容，不解密 TLS 正文，也不能直接等同于手机中某个已安装应用的流量。

06

批次确认、一致性与故障边界

内核在原有 API 端口注册 /xray.app.stats.command.DomainTrafficService/GetBatch。请求与响应使用 google.protobuf.Struct，使面板可在不替换其上游 Xray Go 模块依赖的情况下读取扩展。内核字节数、序号和溢出计数采用十进制字符串，避免 Struct 数字转换造成 64 位精度损失。

机制实现含义
coreId每个内核实例生成新的随机 ID，区分重启前后的序号空间。
sequence当前实例内递增；面板以 coreId / sequence 的已提交检查点去重。
不可变 pending 批次在收到相符 ACK 前重复返回同一批记录；后续新流量仍进入其他缓冲桶。
单事务客户身份、域名字典、分钟 / 日用量、采样状态及检查点共同提交。
重试请求超时或写库失败后重读。已提交的批次不再次累加用量。
单一持久消费者由本机面板负责确认；运维 CLI 可以只读查看，避免另外手动推进 ACK。

保证范围

该协议保证同一运行实例下的重试去重与提交后确认。内核没有持久化日志或磁盘 spool；核心崩溃、被替换或重启时，尚留在内存中的最后一段数据可能丢失。不能把这套分析数据描述成跨进程崩溃的严格计费账本。

07

服务分类与紧凑规则库

Google、Facebook 只是服务库中的例子，不是统计白名单。所有已计量的目标都尝试分类：匹配到服务时归到服务键，未匹配品牌时保留原始主机名并按可注册主域名归类；无法取得域名时保留 unknown 分组。

生成与加载

tools/serviceindex 通过现有 GeoSite 流式读取器生成 traffic-services.idx，排除常见地理、广告等聚合集合及过大的分类候选。同一条规则重叠时先采用条目较少的候选，配合更具体域名优先匹配。这是可维护的规则归类，不是应用身份的确定证明。

精确 / 后缀规则按 SHA-256 排序，每行 32 字节摘要 + 4 字节服务 ID；头部保存服务表、源文件摘要与生成时间。关键词 / 正则规则数量限制为 1024。加载端限制文件大小到 32 MiB、头部到 1 MiB，匹配缓存最多 4096 项。分类工作发生在写库事务之外。

匹配顺序结果
用户覆盖具体主机先于父域；覆盖规则优先于内置规则。
精确 / 后缀域名先尝试完整主机，再逐级检查父域后缀。
受限关键词 / 正则按生成索引中的规则顺序继续识别。
未知品牌docs.example.org → domain:example.org，域名明细仍保留完整主机名。
未知域名__unknown__ → unknown；不因无法识别品牌而丢弃已计量字节。

2026-11-08 部署的索引约 1 MiB，包含 1427 个分类、28663 条精确 / 后缀域名规则；这是该次数据快照，不是软件固定常数。

更新与覆盖

go run ./tools/serviceindex -in /path/to/geosite.dat -out traffic-services.idx

索引默认放在 Xray 二进制目录，或通过 XUI_SERVICE_INDEX 指定路径。自定义分类放在面板数据库目录的 service-overrides.json；部署实例对应 /etc/x-ui/service-overrides.json：

{
  "example.com": "业务系统"
}

文件变化约一分钟内重新检查并载入。缺少索引时仍按域名降级记录；配置错误显示在采集状态中。历史保留当时的分类，不追溯改写，域名字典的唯一键因此包含 host 与 service。

识别局限

共享 CDN、ECH、IP 直连、连接复用和协议目的地变化都可能降低归类准确度。域名归类描述可见的访问目标，不能保证等同最终产品品牌、已安装应用或具体网页。

08

存储模型、索引与保留策略

所有新增表由既有 GORM AutoMigrate 创建，保存于原面板数据库。核心路径 /etc/x-ui/x-ui.db 沿用既有备份方式。时间保存为 Unix 秒，字节保存为整数；接口中的时间字段不要当作毫秒。

表关键键 / 字段职责
client_traffic_history_clientsclient_id；email、comment总量 / 站点历史共用的客户身份快照，无级联删除。
client_traffic_history_buckets(client_id, source_id, bucket_start)；up、down客户总量分钟桶；时间和客户时间索引支持范围查询。
client_traffic_history_polls(source_id, bucket_start)；last_sample成功采样分钟和最近采样时间。
traffic_domains(host, service) 唯一；id域名 / 服务组合字典，避免每个分钟桶重复保存长字符串。
client_domain_traffics(client_id, domain_id, bucket_start) 唯一域名分钟明细；客户时间、时间和域名索引。
client_service_daily_traffics(client_id, service, day_start) 唯一按采集时面板时区归档的服务自然日汇总。
domain_traffic_checkpointscore_id；sequence、updated_at已提交批次的确认点。
domain_traffic_statusesid=1；enabled、core_id、last_sample、overflow、error当前采集状态；不等同数据库中的启用偏好。
domain_traffic_pollsbucket_start；last_sample站点采样覆盖，用于区分缺口和已采到的零流量。

两种保留策略

数据默认保留可配置项 / 处理方式
客户总量分钟历史长期保留当前实现没有自动删除；需要监控数据库增长。
域名分钟明细30 天XUI_DOMAIN_DETAIL_DAYS；允许 1～3650 天，非法值回落默认。
服务自然日汇总365 天XUI_DOMAIN_SUMMARY_DAYS；允许 1～3650 天，非法值回落默认。
站点采样覆盖 / 旧确认点跟随汇总保留窗口定期删除过期条目。

域名采集任务约每 10 分钟触发一次分批清理：每种用量表一轮最多删除 10000 条过期行，并清理不再引用的域名字典。它通过限制单次事务工作量减少对原用量写入的阻塞，并不是磁盘大小的硬上限。

配置保留时间时，应让服务汇总窗口不短于域名明细窗口；当前两个环境变量独立解析，不会自动纠正彼此关系。清理主要释放数据库内部页，文件是否缩小还取决于 SQLite 后续复用及运维维护。

09

时间查询、聚合粒度与图表质量

范围语义

API 采用左闭右开 [from, to)，起点向下、终点向上对齐到分钟。最近 1 / 7 / 30 天是滚动窗口，而不是“今天 / 本周 / 本月”。保存的时间戳是 UTC；小时刻度和自然日边界按面板时区计算。

对齐后的查询长度总量 / 近期站点查询的默认粒度说明
不超过 6 小时分钟适合查看短时突发；最多约 360 个分钟区间。
超过 6 小时，不超过 14 天小时最近 1 天和 7 天使用此粒度。
超过 14 天，不超过 180 天自然日最近 30 天默认按日；首尾区间可能不足一天。
超过 180 天，不超过 3 × 366 天自然周周一作为周边界。
超过 3 × 366 天月 / 多月按跨度增加月份步长，控制超长范围的返回点数。

自然日按日历边界推进，不固定切成每段 86400 秒，因此可表达夏令时的 23 / 25 小时日。查询在同一数据库读事务中计算汇总、明细与图表，使用参数化 SQL、时间索引和 ranges CTE，避免把全部分钟记录拉到浏览器。

超出域名明细保留窗口

当查询起点跨过明细保留边界且系统确实已有旧采集历史时，整段查询切换到服务日汇总，首尾扩展到完整自然日，返回 archived=true 和实际 from/to。此模式最细为日，不提供已过期的具体 host 查询。保留边界有约两分钟宽容，以避免默认近 30 天窗口因请求延迟频繁切换归档模式。

旧日汇总采用采集时的面板时区。改变面板时区不会重排已经归档的历史日，因此跨时区维护后解读旧日数据要结合归档时区。

缺口与零流量

区间情况图表行为解释
有采样覆盖、无用量显示 0说明该分钟存在成功采样，并未记录字节。
无覆盖、无用量使用 null，跳过该区间的柱形不能把未采集时间伪造为零流量。
部分覆盖且有用量显示已记录值并提示缺口显示的是已知部分，不能自动补足完整区间。
有用量但覆盖元数据不足保留用量并提示缺口不因缺少覆盖字段而隐藏已保存字节。

uPlot 使用自定义矩形路径绘制堆叠柱：下载在下、上传在上，柱高表示该区间的合计字节。矩形按区间起止时间定位，首尾不足整小时或整日的区间仍正确对齐；缺少覆盖的空区间不绘柱。悬浮提示显示区间起止、上传、下载、合计和缺口状态，图例可独立显示或隐藏两个方向。

coveredMinutes 来自成功采样分钟，expectedMinutes 来自实际区间时长；客户总量视图按来源采样分钟去重合并覆盖，它不是“每条连接或每个远程节点均完整采集”的证明。

合计不一致的常见原因

网站统计启用时间可能晚于总量历史；两者采样与边界归属不同；网站视图可能有额外筛选；前 100 排行并非全部数据；远程节点、资源上限或重启末尾还可能产生细分缺口。未知品牌本身不会让已计量字节消失。

API 契约与重启式采集开关

HTTP 接口沿用面板登录与现有 API 授权，返回统计字段，不返回 UUID、密码或订阅凭据。以下路径不包含部署实例的 webBasePath；集成时需加上实际前缀。HTTP 响应保留 success / msg / obj 外壳。

方法 / 路径用途主要参数
GET /panel/api/clients/traffic-history/options客户选项、面板时区、采集起止无；保留已删除客户入口。
GET /panel/api/clients/traffic-history客户总量、图表与客户明细clientId, from, to
GET /panel/api/clients/domain-traffic站点汇总、图表、服务 / 域名排行与采集状态clientId, from, to, service?, domain?, search?

clientId=0 代表所有客户；时间为 Unix 秒，结束必须大于开始。service 和 domain 是精确筛选，search 是子串筛选。域名最长 253 字符，service 最长 512 字符，search 最长 128 字符。完整 schema 由 Go DTO 生成，参见项目 frontend/public/openapi.json。

开关状态与执行顺序

  1. 网页切换只改变草稿；点击“保存并重启 Xray”后才发送请求。
  2. 服务层在进程生命周期锁内读取实际状态；开启前检查正在运行的内核是否支持扩展 RPC。
  3. 保存数据库设置 domainTrafficEnabled，默认 false；构建配置时合并 env.XRAY_DOMAIN_STATS=1/0，保留其他环境项，覆盖父进程和模板中的同名值。
  4. 强制重启本机 Xray，不把环境切换交给热更新；新进程创建或不创建域名采集器。
  5. 通过 RPC 确认实际模式后才返回成功。已经生效的相同设置不再次重启。
{
  "configured": true,
  "running": true,
  "supported": true,
  "enabled": true,
  "error": ""
}

configured 是保存偏好，enabled 是内核实际模式。重启或确认失败时保存值仍保留，界面显示差异和错误，修复原因后可再次应用。该重试机制不等同自动恢复旧内核或旧数据库；进程启动失败时仍需检查日志和服务状态。

业务影响

重启会断开当前连接，客户端需重新连接；内核未导出的最后一段细分流量可能丢失。已经入库的历史保留。关闭只影响网站细分采集，原客户总量与额度继续工作；原路由嗅探也不被此开关关闭。

安全与故障定位

扩展 RPC 复用本机 loopback 端口，不增加公网统计监听；Web API 沿用登录、API 授权和适用的 CSRF 保护。域名历史本身属于访问元数据，应和原面板数据库一起限制读取权限。本文不包含实际登录口令、客户 UUID、私钥或订阅令牌。

现象优先检查
客户总量正常，网站采集不可用实际内核是否为定制版本；开关保存值与实际值；RPC / 规则库错误。
开启后短时间尚无新图表先确认内核 enabled，再等待 5 秒采集与页面刷新；启用前历史不能反推。
规则库未加载索引路径、文件权限、文件校验及 overrides 格式；仍按域名降级记录。
图表存在缺口或溢出提示采集任务错误、重启时段、缓冲触顶和保留窗口。
保存设置后状态不一致查看启动日志，修复配置 / 端口 / 二进制问题后重新应用。
REALITY 验证收到普通站点证书先排查测试链路是否被另一层代理重写目标；不要仅凭这一日志判断统计内核有故障。

本次曾确认一个本机验证问题：WSL 流量被 Windows TUN 送入开启 TLS 目标覆盖的代理，服务器 IP 被改写为伪装域名；原生 Windows 直连及仅用于路由的对照均正常。排查时应把“测试客户端自身的路由链路”与“服务器计量改造”分开验证。
