# 网站与服务流量统计

在“客户流量统计”页面选择“网站与服务”。客户和时间条件与原有总量统计共用，支持所有客户、单个客户、近 1 / 7 / 30 天和自定义起止时间。

页面提供服务和域名排行、上传/下载/合计、占比、双曲线及搜索。点击服务查看其域名，点击域名筛选该站点。排行显示所选范围内的前 100 项，并显示完整项目数量。

## 数据链路

定制 Xray 26.10.31 内部按连接计量，通过既有 loopback StatsService 端口提供扩展 RPC。面板每 5 秒取一个批次，写库后保存确认序号，下次请求才确认。相同 core ID / 序号重复到达时不重复入账；核心重启使用新的随机 ID。

客户端协议、订阅地址、额度规则保持兼容。域名统计与额度清零分开；删除客户仍可查询已经落盘的历史。当前接入的是本机定制内核，未升级的远程节点不能提供这项细分数据。

默认的官方内核不支持此 RPC，页面会显示采集不可用，而原有客户总量统计继续工作。

## 采集开关

页面顶部提供“网站流量采集”开关和“保存并重启 Xray”按钮。开关先修改待保存的选择，点击按钮才会保存并重启本机 Xray。当前连接会中断并由客户端重新连接；最后尚未导出的内存流量可能丢失，已经入库的历史不会清空。

设置存入数据库的 `domainTrafficEnabled`，默认关闭。每次启动都会把该值写入生成配置的 `env.XRAY_DOMAIN_STATS`（`1` / `0`），优先于父进程和模板中的同名值，其他环境配置保留。因此面板、内核或服务器重启后仍采用保存的选择；无需修改 systemd 环境变量。

页面同时展示保存的选择和内核通过 RPC 返回的实际状态。重启或状态确认失败时会显示错误，保存值仍保留，可修复原因后再次点击按钮。已经生效的相同设置不会再次重启。开启前会检查正在运行的内核是否支持细分统计 RPC，避免在官方内核上误报开启成功。

关闭后新内核不创建域名采集器、不增加统计专用嗅探、不启用统计专用 Vision splice 路径。原有路由嗅探设置、客户总量及额度统计继续工作。采集关闭期间无法重建站点历史，页面保留查询入口并提示统计缺口。本开关仅控制本机内核，不修改远程节点。

## 服务分类

`tools/serviceindex` 从既有 GeoSite 数据生成紧凑的 `traffic-services.idx`。索引包括精确域名、后缀、受限数量的关键词/正则规则；通用地理、广告集合等聚合类别不作为服务品牌。相同规则优先采用范围更具体的分类。

运行时载入排序的 SHA-256 规则索引，避免将整份 GeoSite 展开为 Go 对象。识别结果有上限缓存，分类在数据库事务外完成。Google、Facebook 等只是分类库中的条目，不是固定统计范围。

未知品牌仍按可注册主域名归类，保留原始目标主机名；无法得到目标域名的流量显示为“无法识别域名”。共享 CDN、ECH、连接复用等可能降低归类准确度。仅采集域名和字节数，不记录 URL 路径或解密网页内容。

构建分类库：

```sh
go run ./tools/serviceindex -in /path/to/geosite.dat -out traffic-services.idx
```

将索引放入 Xray 二进制目录。`XUI_SERVICE_INDEX` 可以指定其他路径。缺少索引时仍按域名记录，页面提示分类库未加载。

`/etc/x-ui/service-overrides.json` 可覆盖域名及子域名的服务名称，例如：

```json
{"example.com":"业务系统"}
```

索引或覆盖文件变化约一分钟内重新载入。覆盖规则优先于内置分类。历史记录保留入库时的分类，不追溯重写；规则调整后新记录采用新的分类。

## 存储与资源

- `traffic_domains`：域名/服务组合字典。
- `client_domain_traffics`：客户、域名字典 ID、UTC 分钟的上传和下载。
- `client_service_daily_traffics`：客户/服务自然日汇总。
- `domain_traffic_checkpoints`：已落盘批次的确认序号。
- `domain_traffic_statuses` / `domain_traffic_polls`：运行状态、资源上限提示和覆盖分钟。

默认域名分钟明细保留 30 天，服务日汇总保留 365 天，分别由 `XUI_DOMAIN_DETAIL_DAYS`、`XUI_DOMAIN_SUMMARY_DAYS` 调整。清理分批执行并移除不再引用的域名字典，减少对原有流量写入的阻塞。原有客户总量历史的保留策略不变。

查询较早时间时使用服务日汇总，并明确对齐自然日起止时间；域名明细不可恢复。自然日按采集时的面板时区归档，修改面板时区不会重新分配已经归档的旧记录。记录从启用功能后开始，之前的客户总量不能拆分为站点用量。

内核限制最多 4096 个活跃跟踪会话、16384 个待导出分钟键，每批 1000 条。达到上限时转发继续，页面显示细分记录不完整的提示。核心崩溃时最后未导出的内存记录不能保证恢复，统计用途不应等同严格账单。

## API 与升级

`GET /panel/api/clients/domain-traffic` 使用面板现有认证。参数为 `clientId`、`from`、`to`，以及可选的 `service`、`domain`、`search`。时间使用 Unix 秒，响应包含曲线、排行、运行状态与实际查询范围，不返回连接凭据。

`GET /panel/api/clients/domain-traffic/settings` 返回保存值、内核运行状态、RPC 支持情况和实际开关值。`POST` 同一路径接收 JSON `{"enabled":true}`，保存并重启内核；响应失败时仍可能包含实际状态对象，供界面展示差异并重试。

内核源码独立维护在 `Xray-core` 仓库，基础版本和构建方法见其中 `CUSTOM_KERNEL.md`。升级部署需要同时保留兼容的面板采集器、定制内核及分类索引。官方直接替换内核会覆盖计量扩展；数据库中的已存历史仍保留。

开关与真实内核的回归测试：设置 `XRAY_DOMAIN_E2E_BINARY` 为定制内核的绝对路径，执行 `go test ./internal/web/service -run TestDomainSwitchOverridesInheritedEnvironment -count=1`。测试包含父进程/模板覆盖、进程替换、重复保存、重启持久化、应用失败与重试；不设置变量时跳过该真实内核测试。
